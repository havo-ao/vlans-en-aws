¿Y con IPv6? La misma red, con otra salida

Como quedó · IPv4
Con IPv6 · doble pila
Direcciones
10.0.0.0/16, privadas, las elegimos nosotros
Bloque /56 que asigna AWS: públicas y únicas
Subredes
/24: 251 direcciones útiles
/64 fijo; caben 256 subredes en la VPC
Salida de la aplicación
NAT Gateway: traduce a una IP pública y cobra por hora
Puerta solo de salida: no traduce y no tiene costo
Capa pública
0.0.0.0/0 → puerta de enlace de Internet
Se añade ::/0 hacia la misma puerta
Capa de datos
Sin ruta hacia fuera
Igual: no recibe ruta ::/0
Reglas
Rangos IPv4 y grupos referenciados
Reglas aparte para ::/0 y los /64; las de grupo no cambian
Balanceador
Solo IPv4
Modo doble pila: dualstack

Lo que se añade al código

# La VPC pide un bloque IPv6 y cada subred toma un /64 assign_generated_ipv6_cidr_block = true ipv6_cidr_block = cidrsubnet( aws_vpc.principal.ipv6_cidr_block, 8, 11) # Sin NAT: la aplicación sale por una puerta # que no deja entrar conexiones resource "aws_egress_only_internet_gateway" "salida" { vpc_id = aws_vpc.principal.id } resource "aws_route" "app_ipv6" { route_table_id = aws_route_table.app.id destination_ipv6_cidr_block = "::/0" egress_only_gateway_id = aws_egress_only_internet_gateway.salida.id }

Con IPv6 la dirección privada deja de proteger, porque todas son públicas: el aislamiento lo dan las rutas y las reglas. En doble pila, el NAT se conserva solo para el tráfico IPv4.
