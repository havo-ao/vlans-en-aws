Cómo se hizo · un obstáculo real

La cuenta rechazaba todo… hasta que cambiamos de región

$ aws ec2 describe-vpcs --region us-east-1 An error occurred (UnauthorizedOperation): You are not authorized to perform: ec2:DescribeVpcs with an explicit deny in a service control policy $ aws ec2 describe-vpcs --region us-east-2 VPC CIDR PorDefecto vpc-0cd3464b65d021b35 172.31.0.0/16 True $ aws configure set region us-east-2 # Antes de crear nada: ¿la cuenta permite cada recurso? $ aws ec2 create-nat-gateway --subnet-id … --dry-run DryRunOperation: Request would have succeeded

Síntoma

Red, servidores, base de datos y balanceador respondían «denegado», aun con usuario administrador.

Diagnóstico

El rechazo venía de una política de AWS sobre la cuenta, no de nuestro usuario. La pista estaba en la URL de la consola: us-east-2.

Solución

Trabajar en Ohio y dejar la región como variable en Terraform. Antes de desplegar, se probó cada recurso «en seco».
